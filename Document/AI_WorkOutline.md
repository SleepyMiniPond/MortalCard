# AI 工作指南

## 開始工作

先閱讀本文件、[Coding_Standards](Coding_Standards.md)、[SystemArchitecture](SystemArchitecture.md)、[TODO](TODO.md)，並確認 Git 狀態與既有工作計畫。以程式碼為現況依據，不由過往對話或文件日期推測完成度。

系統導引見 [文件索引](AI_Notes_Index.md)。依任務影響追查 Model、資料配置、Presenter 與 View 的實際消費端；宣告型別存在不代表流程已接線。

## 執行與交付

- 文件、註解及說明使用台灣繁體中文；正式文件聚焦責任、邏輯、限制與程式入口，見 [文件原則](Documentation_Guidelines.md)。
- 臨時設計與分析放在 .agents/working/，不混入 Document，也不納入 Git；長期偏好記錄於 .agents/memory.md。
- 除非明確要求，不 stage、commit 或 unstage 使用者的變更。
- 修改 Assets/Scripts 下 C# 後依專案指令執行 Unity 刷新／重新編譯，修正至 0 error，並回報 warning。
- 交付說明變更、驗證範圍、未解限制及 Git 狀態。既有測試紀錄不冒充本輪驗證。

## 逐步工作與續接

當已有 Markdown 工作計畫，且使用者要求一次一個步驟：

1. 只執行目前步驟；AI 完成實作與驗證後標為「待使用者確認」。
2. 交付明確回報「目前完成第 N 個工作，下一步是第 N+1 個工作」，附驗證與待確認事項。
3. 使用者確認後，立即將目前項目改為「已完成」，更新下一步狀態。
4. 獨立新增問題及衍生工作及時記入計畫，註明插入順序、範圍與狀態；必要時同步調整後續編號。
5. 新對話以計畫中的目前步驟、最近完成、下一步及新增工作為準，再對照程式與 Git。

這項逐步限制只在使用者要求逐步執行時適用；已授權的一整批工作可以連續完成。

## 文件組織

沿用既有領域文件，單一規則集中維護，其他文件引用即可。新增文件依概念命名，不為每支腳本另建說明；暫態統計與詳細 API 清單交由程式查詢。
