# AI 工作大綱 - MortalGame 詳細工作指南

> 💡 **專案背景與技術架構請參見**：[copilot-instructions.md](../.github/copilot-instructions.md)

## 工作原則
1. **優先閱讀**：每次開始任何工作前，必須先閱讀此大綱檔案
2. **系統性分析**：按照系統模組逐一分析，不遺漏任何重要組件
3. **文檔完整性**：確保每個系統都有對應的詳細筆記
4. **交叉引用**：當筆記中提到其他系統時，必須建立適當的引用連結

## 系統模組分析重點

### 核心系統模組
**GameModel** - 核心邏輯層
- 狀態管理、流程控制、事件系統
- 實體系統、動作系統、條件系統、目標系統

**GameView** - 視覺呈現層
- 視覺效果與動畫系統

**UI** - 使用者互動層
- 介面邏輯與用戶交互

**GameData** - 資料定義層
- 所有遊戲資料結構定義

## AI 工作流程

### 已建立工作計畫時的逐步執行

當任務已有工作計畫 Markdown，且使用者要求一次執行一個步驟時：

1. 只執行目前步驟，不提前混入下一步。
2. 實作與驗證完成後，先將目前步驟標示為「待使用者確認」，並回報「目前完成第 N 個工作，下一步是第 N+1 個工作」。
3. 使用者確認目前步驟 OK 後，立即將工作計畫更新為「已完成」，再把下一步標示為「進行中」或「待開始」。
4. 中途發現的額外問題若會延伸成獨立工作，而非目前步驟內可直接修正的內容，必須盡快加入工作計畫，註明插入順序、歸屬與狀態。
5. 新增工作造成順序改變時，必須同步調整編號與下一步摘要，讓後續新對話能依文件直接續接。
6. 新對話開始時，先以工作計畫記錄的最近完成項目、目前步驟、下一步與新增工作為準，再核對程式、測試與 Git 狀態。

## 筆記命名規範

**基本原則**：
- 單一腳本：`CardData.md`
- 系統整合：`Card_System.md`  
- 枚舉參考：`GameEnum_Reference.md`

**命名決策**：
- 單一職責 → 直接使用腳本名
- 系統整合 → 使用 `_System` 後綴
- 避免冗余後綴（如 `_Class`）
