# 文件撰寫與維護原則

文件用於理解系統責任、遊戲規則與設計限制。程式碼是現況依據；文件不複製欄位、完整型別清單、方法參數或逐步實作。

## 應保留的內容

- 系統為何存在，與相鄰系統如何分工。
- 主要資料流、狀態轉移、順序與不可破壞的規則。
- 正常失效、取消、持久化與驗證的責任邊界。
- 關鍵程式入口，以及尚未接線的能力。

同一規則由一份領域文件維護，其他文件以連結引用。QA、圖表與新文件只在能改善理解時使用，不要求每個資料夾都有筆記。

## 現況、計畫與歷史

- 系統文件只描述已核對的行為；預留型別、列舉成員或資料欄位不代表功能完成。
- TODO 分開記錄既有基礎、剩餘工作、決策與完成條件；不因測試類別存在就宣稱驗收通過。
- 封存文件保留當時結果與日期；歷史數量、警告及臨時工具不當作目前狀態。
- 流程規範是未來工作的要求，不應寫成現有程式已完全符合。
- 草稿留在 .agents/working/；正式文件不依賴臨時草稿才能理解。
